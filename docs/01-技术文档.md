## 1. 项目定位与总体架构

个人博客系统：**单体架构、前后端分离**。前后端是两个独立工程，仅通过 RESTful API + JSON 通信，可完全并行开发（前端用接口文档 mock，后端只管吐统一结构）。

```
┌─────────────────────────┐         HTTP (JSON, CORS)        ┌──────────────────────────────┐
│  frontend  (Vue 3 SPA)  │  ─────────────────────────────▶  │  backend (Spring Boot 单体)   │
│  Vite :5173             │        /ping  /api/v1/**         │  :8080                       │
│  Element Plus           │  ◀─────────────────────────────  │                              │
│  Pinia / Vue Router     │        Result<T> 统一结构         │  Controller → Service → Mapper│
└─────────────────────────┘                                  └──────────┬─────────┬─────────┘
        静态资源生产期由 Nginx 托管，/ping、/api/** 反代到后端              ▼         ▼
                                                                  MySQL 8    Redis
```

**关键决策与理由**

| 决策 | 理由 |
|---|---|
| 单体而非微服务 | 个人博客的流量与团队规模用不上微服务；单体部署简单（一个 jar），拆分成本远大于收益 |
| 前后端分离 + 并行开发 | 接口先行（见接口文档），前端靠 Axios 拦截器 + TS 类型契约开发，后端按同一文档实现 |
| 生产同源部署 | Nginx 托管前端静态资源并反代 API，天然无跨域、无需 CORS；开发期才走 CORS 直连 |
| Java 21 虚拟线程 | `spring.threads.virtual.enabled=true`，IO 密集的 Web 请求用虚拟线程承载，高并发下吞吐更好，业务代码零改动 |

## 3. 分层职责与调用规则

**调用方向严格单向：`Controller → Service → Mapper`，禁止跨层（Controller 不碰 Mapper，Service 不碰 HttpServletRequest）。**

| 层 | 职责 | 明确不做 |
|---|---|---|
| controller | 参数绑定与校验触发（@Valid）、调 Service、把结果包成统一结构返回、Swagger 注解 | 业务逻辑、直接返回 entity |
| service | 业务编排与领域规则、业务异常（BusinessException）、事务边界（**预留，由你实现**）、DTO↔entity 转换 | 写 SQL、拼 HTTP 语义 |
| mapper | 继承 BaseMapper<T>，仅数据访问；复杂 SQL 用 XML（resources/mapper/） | 业务判断 |
| dto | 入参 + jakarta.validation 校验注解 | — |
| vo | 出参，只含前端需要的字段 | — |
| common | 响应契约、错误码、全局异常（横切，所有层可用） | 业务逻辑 |
| config | 框架装配（CORS/文档/ORM 基础设施） | 业务 Bean |

数据流转：`请求 → DTO → service（转 entity）→ mapper → entity → service（转 VO）→ Result<VO>`。
**entity 永不出 Service 层**——数据库结构变化不冲击接口契约，这是 DTO/VO 存在的理由。

> 例外：健康检查 `/ping` 直接在 Controller 返回，不经过 Service（探活接口没有业务规则）。

## 4. 开发规范

### 4.1 命名约定

| 对象 | 约定 | 示例 |
|---|---|---|
| Java 包 | 全小写，按层+模块 | `com.winxin.blog.service.article` |
| 类 | 大驼峰；Controller/Service/Impl/Mapper/DTO/VO 后缀体现层级 | `ArticleController`、`ArticleServiceImpl`、`ArticlePageQuery`、`ArticleDetailVO` |
| 方法 | 小驼峰动词开头 | `publishArticle`、`listByPage` |
| 常量 | 全大写下划线 | `SUCCESS_CODE` |
| 数据库 | 表/字段小写下划线；表名单数；时间字段 `*_at`；布尔/状态用 tinyint | `user`、`published_at`、`status` |
| 接口路径 | 复数名词资源 + HTTP 动词表达操作；版本前缀 `/api/v1` | `POST /api/v1/articles` |
| 前端组件文件 | 大驼峰 .vue；视图以 View 结尾 | `BasicLayout.vue`、`HealthView.vue` |
| 前端组合式函数/变量 | `useXxx`（store/函数）、小驼峰变量 | `useUserStore`、`result` |
| 前端 API 模块 | 与后端模块一一对应，函数名 = 动作 | `api/article.ts` 的 `publishArticle()` |

### 4.2 接口规范（详见 03-接口文档.md）

- 所有响应（含异常）统一 `Result<T> { code, message, data }`，分页统一 `PageResult<T> { list, total, page, pageSize }`；
- `code=0` 成功；错误码分段：10000+ 通用 / 11000+ 认证 / 12000+ 文章 / 13000+ 用户 / 14000+ 评论 / 15000+ AI；
- HTTP 状态码如实反映传输语义（400/401/403/404/405/500），由全局异常处理器统一设置，body 里 Result.code 与之对应；
- 时间统一 ISO-8601 字符串（`2026-10-26T23:30:29+08:00`），前端 `new Date()` 可直接解析；
- 登录态（预留）：`Authorization: Bearer <JWT>` 请求头，前端在 Axios 请求拦截器统一附加。

### 4.3 Git 分支策略

```
main        ── 可发布：只接受 PR/MR，打 tag（v0.1.0）
  └── dev            ── 集成分支：功能完成后合入，保持可运行
        ├── feature/article-crud   ── 一个功能一个分支，命名 feature/<模块>-<内容>
        └── fix/avatar-upload-404  ── 修复分支
hotfix/xxx  ── 从 main 切出修线上问题，修复后同时回合 main 与 dev
```

- 提交信息用 Conventional Commits：`feat: 文章分页列表` / `fix: 拦截器 401 未跳转` / `docs: 补充接口文档` / `chore: 升级 springdoc 3.2.0`；
- `package-lock.json` 与 pom 版本变更必须随代码一起提交，保证任何人 clone 后构建一致。

## 5. 多环境与敏感配置

| 配置 | dev 默认值 | 生产注入方式 |
|---|---|---|
| 激活环境 | 不设变量 → dev | `SPRING_PROFILES_ACTIVE=prod` |
| 数据库 | `MYSQL_HOST/PORT/DATABASE/USERNAME/PASSWORD`（未设变量用本地默认） | 同名环境变量，**无默认值**，缺失即 fail-fast |
| Redis | `REDIS_HOST/PORT/PASSWORD/DATABASE` | 同上 |
| CORS 来源 | `APP_CORS_ALLOWED_ORIGINS`（默认 localhost:5173 两个变体） | 必填，禁止 `*` |
| 接口文档 | 开启 | prod 自动关闭（application-prod.yml） |

原则：**配置文件里永远不出现真实密码**；dev 的默认值仅为本机起服务方便，上线以环境变量为准。

## 6. 跨域与部署方案

- **开发（默认）**：前端 5173 直连 8080，后端 `WebMvcConfig` 按 `app.cors.allowed-origins` 精确放行（allowCredentials，禁止通配符）。健康检查页即验证此链路。
- **开发（备选）**：不想暴露 CORS 时启用 vite.config.ts 中注释的 proxy，并把 `VITE_API_BASE_URL` 置空——两方案二选一。
- **生产**：前端 `npm run build` 产物由 Nginx 托管；`VITE_API_BASE_URL` 留空（同源），Nginx 反代：

```nginx
server {
    listen 80;
    root /var/www/winxin-blog/dist;
    location / { try_files $uri $uri/ /index.html; }   # SPA history 路由回退
    location ~ ^/(ping|api|v3/api-docs) { proxy_pass http://127.0.0.1:8080; }
}
```

## 7. Spring Boot 4 相比 3.x 的主要差异（本项目已按 4.x 写法落地）

> 依据：Spring Boot 4.0 官方迁移指南（github.com/spring-projects/spring-boot/wiki → Spring Boot 4.0 Migration Guide）与 4.1.2 发布公告（spring.io/blog/2026/10/23）。

1. **自动配置模块化**：3.x 的"巨型 `spring-boot-autoconfigure`"被拆成按技术划分的模块（`spring-boot-webmvc`、`spring-boot-jackson`、`spring-boot-data-redis`、`spring-boot-tomcat`…）。**starter 名称保持兼容**——本工程用 `spring-boot-starter-web`，它 4.1.2 的 POM 聚合的正是 `spring-boot-webmvc + spring-boot-starter-jackson + spring-boot-starter-tomcat + spring-boot-http-converter`（已在 Maven Central POM 核实）。影响最大的是**第三方 starter**：必须用声明适配 Boot 4 的版本（本项目因此选 `mybatis-plus-spring-boot4-starter`、`springdoc 3.x`、`spring-ai 2.0.x`）。
2. **Jackson 2 → Jackson 3**：groupId/包名从 `com.fasterxml.jackson.core/databind` 改为 `tools.jackson.*`；**注解包保持 `com.fasterxml.jackson.annotation`**（如本工程 Result 上的 `@JsonIgnore`，无需改 import）。JSON 配置仍走 `spring.jackson.*` 属性。
3. **基线抬高**：Java 17 起步（本工程 target 21）；Jakarta EE 11（Servlet 6.1）；Spring Framework 7 / Spring Security 7；Tomcat 11。本机验证日志：`Spring Boot v4.1.2, Spring v7.0.10, Tomcat/11.0.27`。
4. **Bean 扫描变化冲击第三方集成**：Framework 7 改了 `ClassPathBeanDefinitionScanner` 相关 API，旧版 MyBatis/MyBatis-Plus 的 mapper 扫描在 Boot 4 下自动配置失效（MP 3.5.15 曾报 `Invalid...` 错误，见其 issue #7009），**必须用适配版 starter**，且不要再手动引入 `mybatis`/`mybatis-spring` 拼版本。
5. **3.x 弃用项被移除、部分属性迁移**：升级老项目时挂官方 `spring-boot-properties-migrator` 依赖启动一次，它会报告并临时映射被改名的属性；新项目（本工程）直接按 4.x 属性写即可。
6. **虚拟线程**：`spring.threads.virtual.enabled=true`（3.2 引入、4.x 沿用），Tomcat 请求处理即切虚拟线程，无需改代码。
7. **API 版本化**：Framework 7 内置了 REST API 版本支持（本工程用 URL 路径版本 `/api/v1`，两者不冲突，后续可评估）。

## 8. 预留扩展点（按边界约定，由你实现）

| 扩展点 | 建议接入位置 |
|---|---|
| Spring Security + JWT | 新增 `security/` 包配 SecurityFilterChain；JWT 工具放 utils；前端 store/user.ts + request.ts 的 TODO 处补充 Token 附加与 401 跳转 |
| 自定义注解 + AOP（权限/操作日志） | 新增 `annotation/` + `aspect/` 包；需引入 `spring-boot-starter-aop` |
| 事务边界 | Service 实现时用 `@Transactional`（注意：虚拟线程不影响事务语义） |
| 缓存策略 | 建议用 `@EnableCaching` + RedisCacheManager（starter 已就位），文章详情/列表是第一候选 |
| AI 模型接入 | pom 已引入 spring-ai-bom 2.0.2，取消注释对应 starter（如 spring-ai-starter-model-openai）即可；接口契约已在 03 文档 AI 模块定义 |
